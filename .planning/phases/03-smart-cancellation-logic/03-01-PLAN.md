# Plan 03-01: Redesign Notification Scheduling with Date-Specific Identifiers

## Context

**Problem:** Phase 2 uses repeating notifications (`repeats: true`) with static identifiers ("lunch-reminder", "evening-reminder"). When Phase 3 cancels by identifier, iOS cancels ALL future recurrences, not just today's notification. This breaks the requirement that notifications continue tomorrow after logging today.

**Solution:** Redesign Phase 2's `ScheduleNotificationsUseCase` to schedule 30 individual non-repeating notifications with date-specific identifiers (e.g., "lunch-reminder-2026-02-28", "evening-reminder-2026-02-28"). This allows Phase 3 to cancel only today's notifications while preserving future days.

**Architectural Decision:** User selected Option A from research checkpoint. This plan modifies the existing Phase 2 scheduling logic to enable future cancellation in Phase 3.

**Timing Clarification:** Per CONTEXT.md, notifications are "scheduled for next 30 days upfront (on first launch or after cancellation)". This plan modifies Phase 2's existing first-launch scheduling. Future re-scheduling after cancellation will be addressed in a separate plan if needed after Phase 3 testing.

**Requirements Coverage:**
- NOTIF-11: Enables targeted cancellation for "today" only
- NOTIF-12: Supports cancellation regardless of data type
- NOTIF-13: Uses date-specific identifiers matching app's calendar logic
- NOTIF-14: iOS notification system persists date-specific schedules across force-quit

## Goal

Modify `ScheduleNotificationsUseCase` to schedule 30 days of individual non-repeating notifications with date-specific identifiers instead of 2 repeating notifications with static identifiers.

   ```swift
   // Schedule 30 days of notifications upfront
   let calendar = Calendar.current
   let today = calendar.startOfDay(for: Date())

   for dayOffset in 0..<30 {
       guard let targetDate = calendar.date(byAdding: .day, value: dayOffset, to: today) else {
           continue
       }

       let dateString = formatDateForIdentifier(targetDate)
       let (lunchComponents, eveningComponents) = notificationTiming(for: targetDate)

       // Schedule lunch notification (NOTIF-05, NOTIF-07)
       try await notificationService.scheduleNotification(
           identifier: "lunch-reminder-\(dateString)",
           title: Bundle.main.object(forInfoDictionaryKey: "CFBundleDisplayName") as? String ?? "HealthTracker",
           body: "Registre o que você comeu hoje",
           dateComponents: lunchComponents,
           repeats: false
       )

       // Schedule evening notification (NOTIF-06, NOTIF-08)
       try await notificationService.scheduleNotification(
           identifier: "evening-reminder-\(dateString)",
           title: Bundle.main.object(forInfoDictionaryKey: "CFBundleDisplayName") as? String ?? "HealthTracker",
           body: "Registre suas refeições e atividades",
           dateComponents: eveningComponents,
           repeats: false
       )
   }
   ```

   ```swift
           eveningComponents.hour = 20
   ```

5. **Add helper method for date formatting**:
   ```swift
   /// Formats a date as a string for use in notification identifiers.
   /// - Parameter date: The date to format
   /// - Returns: Date string in "yyyy-MM-dd" format (e.g., "2026-02-28")
   private func formatDateForIdentifier(_ date: Date) -> String {
       let formatter = DateFormatter()
       formatter.dateFormat = "yyyy-MM-dd"
       formatter.calendar = Calendar.current
       return formatter.string(from: date)
   }
   ```
