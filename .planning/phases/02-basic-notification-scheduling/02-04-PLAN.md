# Phase 02 Plan 04: Use Dynamic App Name for Notification Title

**Goal:** Use CFBundleDisplayName from project configuration for notification title instead of hardcoding app name

**Context:** Phase 2 verification found that notifications hardcode "HealthTracker" as the title, while the app's display name is configured as "Monitor de Hábitos Saudáveis" in the project's Info.plist. Using the dynamic CFBundleDisplayName makes notifications adapt to project configuration.

**Gap being closed:** gap-1 (Inconsistent Localization - English Title)

**Note:** This enhances the localization implementation (NOTIF-07, NOTIF-08) by making the notification title dynamic based on project configuration rather than hardcoded. The implementation retrieves CFBundleDisplayName from Info.plist with a fallback to "HealthTracker".

## Notes

**Design decisions:**
- Using CFBundleDisplayName from project configuration makes notifications adapt dynamically to project settings
- Provides consistency across iOS system (app icon label, notifications, Settings app, etc.)
- Fallback to "HealthTracker" ensures graceful degradation if CFBundleDisplayName is not configured
- No hardcoded app name in notification code - configuration-driven approach

**Risk assessment:**
- **Risk:** Low - Simple Bundle API call, no complex logic or architecture modifications
- **Testing:** Existing test suite provides safety net, updated test verifies dynamic behavior
- **Rollback:** Trivial - can revert to hardcoded "HealthTracker" if needed

**Alternative considered:**
- Hardcoding Portuguese-BR "Monitor de Hábitos Saudáveis" directly in code
- **Rejected because:** Less flexible, requires code change if app name changes in project configuration. Dynamic approach is more maintainable.
