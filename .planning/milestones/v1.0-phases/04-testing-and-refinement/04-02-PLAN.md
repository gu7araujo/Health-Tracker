## Notes

**Why manual testing for edge cases?**
iOS system behaviors (time zone, DST, force quit) involve OS-level state that can't be meaningfully unit tested. Manual device testing is industry standard for iOS notification integration.

**Why 10 tests vs 6 in Phase 3?**
Phase 4 is comprehensive validation phase. Phase 3 UAT focused on smart cancellation only. Phase 4 covers full system: unit tests, debug/production timing, permissions, edge cases.

**Debug configuration reference:**
Phase 2 implemented #if DEBUG conditional compilation for testable times. Test 2 verifies this works. Test 3 verifies production times unchanged.

**Test execution order:**
Executor can run tests in any order, but logical flow:
1. Unit tests (fast, catches regressions)
2. Debug mode (rapid validation)
3. Production mode (time-consuming but critical)
4. Edge cases (thorough validation)

**Pass/fail criteria:**
Each test has objective criteria. No subjective judgments. Either notification fires or it doesn't. Either app crashes or it doesn't.

**Update protocol:**
Executor updates UAT.md as testing progresses:
- Mark test results as pass/fail
- Add notes with observations
- Update Summary counts
- Document gaps if found
- Update "Current Test" to track progress
